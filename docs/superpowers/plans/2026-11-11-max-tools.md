# MAX Tools Implementation Plan

**Goal:** Repair screenshot failures with real reviewed device actions, runnable HTML,
safe output handling and working speech fallbacks, then deliver a signed APK update.
**Architecture:** Native Java typed plans, accessibility controller/overlay, private
HTML artifacts and sandboxed WebView, explicit model intent parsing. Existing SQLite
and Keystore remain; no new backend/account.
**Spec:** docs/superpowers/specs/2026-11-11-max-tools-design.md

## Global constraints

- minSdk26,target35; no AndroidX requirement; Arabic RTL; same signing key/package.
- Never send/post without final review, or interact with a locked/wrong app window.
- HTML preview has no native bridge, file/content or network access.
- No real account messages/posts during QA; preserve secrets and old records.

## Ownership

Root: MainActivity, ai/** (except agents' tests), voice policy/controller, manifest,
version/build/release/docs and final integration. Device agent: automation/** and
its tests. HTML agent: preview/**, data/AppStore.java, preview IDs and its tests.
QA agent: official emulator/WebView setup, isolated fixtures, docs/qa/** and QA scripts.
Independent domains are delegated under dispatching-parallel-agents; no shared file
mutations. Agent contracts are fixed in their task packets and root integrates them.

## Tasks

- [ ] Typed device plans/parser, app resolver, accessibility window guards and visible
      foreground controller with one-shot final confirmation.
- [ ] Private HTML artifact store, calculator HTML, safe document extraction, actual
      sandboxed preview Activity, database migration and chat artifact metadata.
- [ ] Root intent dispatcher and prompt integration; null prevention; speech fallback
      and draft preservation; app manifest/version integration.
- [ ] Official working-WebView emulator plus fake social/speech fixtures and genuine
      UI/JS/permission/upgrade checks; relevant unit suite and lint/build.
- [ ] Review integrated result, fix meaningful failures, publish verified APK/source
      and document limits using an immutable public download and state receipt.

## Review focus

Unconfirmed/double final commits; edited drafts or wrong recipient/app between review
and click; locks/process interruption; malformed/huge HTML and remote resource attempts;
nullable/truncated provider output; speech unsupported/error loops; schema upgrade data
and signing/Keystore continuity. Each domain owns tests for these boundaries.
